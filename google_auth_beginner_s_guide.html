Step 01

Google Cloud Console 프로젝트 및 자격 증명 설정

구글 로그인을 앱에 붙이기 위한 가장 첫 번째 관문입니다.

1

Google Cloud Console 접속 및 프로젝트 생성

Google Cloud Console(console.cloud.google.com) 에 접속하여 우측 상단의 새 프로젝트 버튼을 클릭합니다. 원하는 프로젝트 이름을 정하고 생성을 완료하세요.

2

OAuth 동의 화면(Consent Screen) 구성

좌측 메뉴에서 API 및 서비스 > OAuth 동의 화면으로 이동합니다.

User Type: 일반 공개 서비스라면 외부(External)를 선택합니다.
앱 정보: 앱 이름, 사용자 지원 이메일, 개발자 연락처 등을 양식에 맞게 입력합니다.
범위(Scopes): 기본값인 .../auth/userinfo.email, .../auth/userinfo.profile, openid 세 가지 기본 권한을 유지하고 저장합니다.
3

OAuth 클라이언트 ID 발급 받기

좌측 메뉴의 자격 증명(Credentials) 탭으로 이동합니다. 상단의 '+ 자격 증명 만들기' 버튼을 클릭하고 'OAuth 클라이언트 ID'를 선택합니다.

💡 애플리케이션 유형 설정 웹 애플리케이션(Web Application)을 선택합니다.
💡 승인된 JavaScript 원본 (중요!) 웹앱에서 구글 로그인 창을 띄울 도메인을 등록합니다.
  • 로컬 테스트용: http://localhost:3000, http://127.0.0.1:5500
  • 배포용: https://yourdomain.com
✓

Client ID 획득 완료!

설정을 완료하고 생성 버튼을 누르면 아래와 같이 생긴 긴 문자열이 담긴 클라이언트 ID를 얻을 수 있습니다. 복사해 두세요!

1234567890-abcdefghijklmnopqrstuvwxyz.apps.googleusercontent.com Client ID 예시
Step 02

프론트엔드(HTML / JavaScript) 소스 코드 구현

사용 중인 웹 페이지에 직접 구글 로그인 버튼을 넣고 구동하는 방법입니다.

구글 공식 신형 SDK인 Google Identity Services (GIS)는 매우 빠르고 심플하게 동작합니다. 아래는 최소한으로 구현 가능한 표준 보일러플레이트 코드입니다.

index.html 
<!DOCTYPE html>
<html lang="ko">
<head>
    <meta charset="UTF-8">
    <title>Google Login Demo</title>
    <!-- 1. 구글 Identity Services SDK 로드 -->
    <script src="https://accounts.google.com/gsi/client" async defer></script>
</head>
<body>

    <h1>구글 로그인 구현 예제</h1>
    
    <!-- 2. 구글 버튼이 렌더링될 실제 요소 -->
    <div id="buttonDiv"></div>

    <script>
        // 3. 구글 로그인이 완료되면 실행되는 콜백 함수
        function handleCredentialResponse(response) {
            console.log("인증 완료! 디코딩된 정보 확인이 필요합니다.");
            console.log("ID Token(JWT): " + response.credential);
            
            // JWT 디코딩 로직 예시 (디코딩 함수는 별도 구현 필요)
            const responsePayload = parseJwt(response.credential);
            console.log("ID: " + responsePayload.sub);
            console.log('이름: ' + responsePayload.name);
            console.log("이메일: " + responsePayload.email);
        }

        // 4. 구글 로그인 설정 초기화 및 렌더링
        window.onload = function () {
            google.accounts.id.initialize({
                client_id: "여기에_발급받은_본인의_CLIENT_ID_입력",
                callback: handleCredentialResponse
            });
            
            // 버튼 디자인 옵션 설정 후 지정된 엘리먼트에 렌더링
            google.accounts.id.renderButton(
                document.getElementById("buttonDiv"),
                { theme: "outline", size: "large", width: 250 }  // 버튼 커스터마이징 가능
            );
            
            // 원클릭 로그인(One Tap)도 활성화 가능
            google.accounts.id.prompt(); 
        };

        // JWT 토큰 파싱 헬퍼 함수
        function parseJwt(token) {
            var base64Url = token.split('.')[1];
            var base64 = base64Url.replace(/-/g, '+').replace(/_/g, '/');
            var jsonPayload = decodeURIComponent(window.atob(base64).split('').map(function(c) {
                return '%' + ('00' + c.charCodeAt(0).toString(16)).slice(-2);
            }).join(''));

            return JSON.parse(jsonPayload);
        }
    </script>
</body>
</html>

1. SDK 로드 & Initialize

구글이 배포하는 최신 자바스크립트 SDK 스크립트를 연결합니다. 그 후 google.accounts.id.initialize에 발급받은 클라이언트 ID와 인증 성공 시 데이터를 수령할 콜백 함수명을 지정해 연동을 준비합니다.

2. 버튼 렌더링 & 원클릭

renderButton()을 통해 구글 디자인 가이드라인에 완전히 맞춘 세련된 순정 구글 버튼을 자동으로 렌더링합니다. 모바일을 대비하여 원터치 스와이프 로그인인 prompt()도 아주 간편하게 한 줄로 구현할 수 있습니다.

로그인 테스트 옵션 선택

도메인과 Client ID가 일치해야 실제 인증 버튼이 정상 동작합니다.

도식으로 이해하는 로그인 과정

1. 사용자가 내 웹앱에서 구글 로그인 버튼 클릭

2. 구글 인증 창에서 본인 계정 비밀번호 입력 완료

3. 구글 인증 서비스에서 내 웹앱으로 **ID Token(JWT)** 발급

4. 웹앱은 JWT 토큰의 Payload를 해석하여 로그인 상태 적용

Step 04

백엔드 서버 연동 및 토큰 무결성 검증

프론트엔드에서 수령한 로그인 정보를 백엔드에서 안전하게 승인하고 세션을 부여하는 방법입니다.

보안 위협 경고: 프론트 정보만으로 회원가입을 처리하면 절대 안 됩니다!

프론트엔드 자바스크립트에서 파싱된 유저 정보(이름, 이메일)만으로 회원가입을 시키거나 로그인을 시켜버리면 해커가 가짜 API 요청을 보내 다른 회원의 이메일로 위장 로그인할 수 있는 보안 취약점이 발생합니다.

따라서 프론트엔드는 구글로부터 받은 원시 ID Token(JWT)을 백엔드 서버로 즉시 전송하고, 백엔드는 구글 서명 라이브러리를 통해 이 토큰의 무결성을 정밀 검증해야 합니다. 

// 1. 필요한 라이브러리 설치: npm install google-auth-library express
const { OAuth2Client } = require('google-auth-library');
const express = require('express');
const app = express();

const client = new OAuth2Client('YOUR_CLIENT_ID');
app.use(express.json());

app.post('/api/auth/google', async (req, res) => {
    const { token } = req.body; // 프론트엔드에서 보낸 ID Token 수신
    
    try {
        // 2. 구글 공식 검증 엔진 가동
        const ticket = await client.verifyIdToken({
            idToken: token,
            audience: 'YOUR_CLIENT_ID', // 반드시 내 앱의 Client ID와 검사
        });
        
        // 3. 디코딩된 진짜 유저 정보 획득
        const payload = ticket.getPayload();
        const userId = payload['sub']; // 고유 사용자 번호
        const email = payload['email'];
        const name = payload['name'];

        // DB 검사 후 로그인 및 자체 세션/JWT 발급 진행
        res.status(200).json({ success: true, user: { userId, email, name } });
        
    } catch (error) {
        // 위조된 토큰일 경우 에러 발생
        res.status(401).json({ success: false, error: '유효하지 않은 토큰입니다.' });
    }
});
# 1. 라이브러리 설치: pip install google-auth fastapi uvicorn
from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
from google.oauth2 import id_token
from google.auth.transport import requests

app = FastAPI()

class TokenData(BaseModel):
    token: str

@app.post("/api/auth/google")
async def verify_google_token(data: TokenData):
    try:
        # 2. 구글 인증 서명 및 만료 시간 자동 검증
        id_info = id_token.verify_oauth2_token(
            data.token, 
            requests.Request(), 
            "YOUR_CLIENT_ID"
        )
        
        # 3. 신뢰할 수 있는 데이터로 회원 가입/로그인 처리
        user_id = id_info['sub']
        email = id_info['email']
        name = id_info.get('name')
        
        return {"success": True, "user_id": user_id, "email": email, "name": name}
        
    except ValueError:
        # 가짜 토큰이나 만료된 토큰일 경우 보안 필터링
        raise HTTPException(status_code=401, detail="유효하지 않은 토큰입니다.")

자주 묻는 질문 (FAQ)

Q. 배포했더니 승인 오류가 발생해요.

대부분 Google Cloud Console의 '승인된 JavaScript 원본' 리스트에 실 서비스의 정확한 주소(포트 포함, 프로토콜 확인 필수)가 누락되어 발생하는 문제입니다. 콘솔에 등록된 URL과 요청을 보낸 도메인이 완벽히 일치해야 합니다.

Q. 백엔드 없이 단순 프론트만으로 개발할 수는 없나요?

백엔드가 아예 존재하지 않는 순수 정적 웹사이트라면 Firebase Authentication 혹은 Supabase와 같은 BaaS(Backend-as-a-Service) 플랫폼을 사용하는 것을 강력 추천합니다. 복잡한 JWT 백엔드 서명 검증을 대행해주기 때문에 보안을 지키면서 프론트엔드 중심으로 빠르게 완성할 수 있습니다.
