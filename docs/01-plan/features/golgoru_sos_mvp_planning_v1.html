골고루 SOS MVP 기획 문서 v1

사용자의 긴급·상담 상황을 AI가 이해하고, 적합한 전문가를 추천한 뒤 전화·문자·상담 요청으로 연결하는 모바일 서비스의 1차 기획 확정본입니다.

Next.js 웹/PWA (MVP) Supabase 백엔드 Gemini AI 추천 Flutter 네이티브 = Phase 2

⚠ 개정 안내 (2026-06-16) — 로그인 정책 반영

이 문서는 v1(2026-06-08) 초기 기획본입니다. 이후 코드와 기획 방향이 다음과 같이 확정되어, 아래 내용으로 읽으십시오. 추천 3~5·기본/긴급 모드·좋아요 only·상태 3종+운영시간·어드민 등록 정책은 유지하되, 일반 사용자 정책은 게스트 탐색 + 로그인 후 AI 추천 확인/전문가 연결로 개정합니다.

  • MVP 소비자 앱 = Next.js 웹/PWA (Flutter 네이티브 앱은 수요 검증 후 Phase 2 옵션).
  • AI 분류 = Next.js 서버 라우트(/api/classify)에서 Gemini 호출 (Edge Function 아님). 직업+카테고리 코드+긴급도 산출.
  • 일반 사용자 로그인 = Supabase Auth OAuth. MVP에서는 카카오톡 로그인과 구글 인증 로그인만 제공한다.
  • 전문가 미니홈피 = 웹 라우트(/expert/[id]). 비로그인 일부 조회는 가능하나 전화/문자 연결은 로그인 후 모바일 브라우저 tel:/sms:로 실행한다.
  • 직업 7개: 변호사·의사·노무사·변리사·세무사·손해사정사·감정평가사 (+ 직업별 카테고리 정규화).
  • Post-MVP(향후): 상담 요청에 대한 전문가 응답 루프·전문가 앱·푸시 알림·전문가 초대메일·좋아요 평가. (테이블만 선반영)
기존 docs/02-design/features/auth-social-login.design.md에는 “입력→추천→전화 비로그인” 정책이 남아 있으므로, 후속 설계 문서 동기화 시 동일한 로그인 게이트 정책으로 개정해야 합니다.

최신 확정 플랜은 golgoru-sos.plan.md / admin-dashboard.plan.md 참조.

1. 서비스 정의

골고루 SOS는 사용자가 본인의 상황을 자연어로 입력하거나 말하면, AI가 의미를 분석하여 적합한 전문가를 3~5명 추천하고, 사용자가 원하는 방식으로 전문가와 연결될 수 있게 하는 서비스입니다.

핵심 방향: 단순 전문가 검색이 아니라 “상황 기반 AI 전문가 추천·연결 서비스”로 정의한다.
사용자 상황 입력
→ Gemini 기반 의미 분석 (직업 + 카테고리)
→ 로그인 확인 / 소셜 로그인 유도
→ 전문가 3~5명 추천
→ 전문가 프로필/미니홈피 확인
→ 전화 / 문자 연결
→ 상담 요청 생성              ◀── 여기까지 MVP (로그인 사용자)
─────────────────────────────
→ 전문가 앱 푸시 알림          ┐
→ 전문가 수락·거절·간단 답변   ├ Post-MVP (향후)
→ 전문가 응답 이력 관리        ┘

3. 모바일 앱 정책

MVP는 Next.js 웹/PWA 단일 앱으로 개발한다. (네이티브 단일 Flutter 앱은 Phase 2 옵션) — 아래 기능 정책은 일반/전문가 역할 정의로 유효하며, 전문가 측 기능은 Post-MVP에 구현.

일반 사용자 기능

  • 비로그인: 메인 일부 기능 조회
  • 비로그인: 전문가 둘러보기 및 전문가 미니홈피 일부 조회
  • 비로그인: 음성 또는 텍스트 상황 입력
  • 로그인 후: AI 전문가 추천 결과 확인
  • 로그인 후: 전화하기, 문자 보내기, 상담 요청하기
  • 로그인 후: 내 기록, 찜, 상담 이력 등 사용자 식별 기능

전문가 기능

  • 전문가 계정 로그인
  • 상담 요청 푸시 알림 수신
  • 상담 요청 상세 확인
  • 수락/거절
  • 간단 답변 메시지 전송
  • 현재 상담 상태 변경

4. 회원 정책

MVP 일반 사용자 정책은 “게스트 탐색 + 로그인 후 추천/연결”로 한다.

회원가입 없이 상황 입력이 가능하다는 기존 검증 결과는 유지한다. 다만 AI 추천 결과 확인과 전문가 연결은 사용자 식별, 상담 이력, 동의 이력, 위치 기반 추천 책임을 위해 로그인 후 제공한다.

비로그인 사용자 허용 범위

  • 메인페이지 일부 기능 조회 가능
  • 전문가 둘러보기 가능
  • 전문가 미니홈피 일부 정보 조회 가능
  • 회원가입 없이 상황 입력 가능
  • 상황 입력 완료 후 AI 추천 결과 표시 전 로그인 유도

로그인 후 허용 범위

  • AI 전문가 추천 결과 확인
  • 추천 전문가 상세 정보 확인
  • 전화하기, 문자 보내기, 상담 요청하기
  • 내 기록, 찜한 전문가, 좋아요 평가 등 사용자 식별 기반 기능

로그인 방식

  • MVP 일반 사용자 로그인은 Supabase Auth OAuth를 사용한다.
  • 초기 제공 방식은 카카오톡 로그인과 구글 인증 로그인 2개로 제한한다.
  • 최초 소셜 로그인은 일반 사용자 계정으로 자동 가입 처리한다.

동의 정책

  • 필수 동의: 서비스 이용약관, 개인정보 수집·이용, 위치 기반 추천을 위한 개인위치정보 수집·이용 동의
  • 선택 동의: 마케팅 정보 수신 및 마케팅 목적 개인정보 활용 동의
  • 마케팅 동의는 서비스 필수 이용 조건으로 강제하지 않는다. 사용자가 마케팅 동의를 거부해도 AI 추천과 상담 연결 핵심 기능은 사용할 수 있어야 한다.
개인정보 수집·이용 동의는 수집 목적, 수집 항목, 보유·이용 기간, 동의 거부권 및 거부 시 불이익을 고지한다. 위치정보 동의는 위치 기반 추천에 필요한 범위로 분리하고, 마케팅 동의는 광고성 정보 전송 동의와 함께 선택 항목으로 관리한다.
참고 법령: 개인정보 보호법 제15조, 정보통신망법 제50조, 생활법령 위치정보 동의 안내.

5. AI 추천 정책

사용자가 어떤 의미로 상황을 설명할지 예측하기 어렵기 때문에, 키워드 검색보다는 Gemini API 기반의 자연어 의미 분석을 활용한다.

추천 수: 기본 상위 3명, 전문가 풀이 충분하면 최대 5명까지 추천한다.

추천 모드

모드추천 우선순위설명
기본 모드 전문 분야 적합도 우선 지역보다 전문 분야와 상황 적합성을 더 중요하게 반영한다.
긴급 모드 전문성 + 지역/거리 + 즉시 대응 가능성 사용자가 긴급 상황임을 선택하면 가까운 전문가와 현재 상담 가능 상태를 더 강하게 반영한다.

AI 추천과 사용자 평가는 구분한다

  • 추천: AI가 상황 분석 후 전문가를 제안하는 행위
  • 좋아요: 실제 상담 후 가입 사용자가 남기는 평가 지표
  • 별점: 도입하지 않음

6. 전문가 등록 및 계정 정책

초기 전문가 등록은 어드민 직접 발굴·검증·등록 방식으로 한다.
  • 어드민이 전문가를 직접 발굴한다.
  • 어드민이 전문가 정보를 입력하고 검증한다.
  • 전문가는 본인 미니홈피 정보를 직접 수정하지 않고 열람 중심으로 사용한다.
  • 향후 서비스 성장 시 전문가 신청 기능을 추가하는 C안으로 확장 가능하게 설계한다.

전문가 계정 활성화

어드민 등록 후 전문가가 초대 링크를 받아 직접 비밀번호를 설정한다.
  1. 어드민이 전문가 기본 정보 등록
  2. 전문가 이메일로 초대 링크 발송
  3. 전문가가 링크 접속
  4. 비밀번호 직접 설정
  5. 계정 활성화
  6. 전문가 로그인
이 초대·활성화 흐름(FR-04)은 Post-MVP다. 현재 MVP는 어드민이 전문가를 데이터로 등록·관리만 한다(전문가 로그인 미사용).

7. 전문가 미니홈피 정책

전문가 미니홈피는 Vercel + Next.js 기반의 독립 웹페이지로 제공한다.
  • 어드민이 전문가 정보를 입력·수정한다.
  • 전문가는 본인 페이지를 뷰 중심으로 확인한다.
  • 사용자가 전문가 카드를 누르면 독립 미니홈피 형태로 열린다.
  • MVP는 웹 라우트(/expert/[id])로 미니홈피를 표시한다. (네이티브 앱 Phase 2 도입 시 WebView)
  • 게시판, 댓글, 전문가 직접 글쓰기는 MVP에서 제외한다.
  • 게시판 기능은 전문가 요청과 시장 반응을 보고 차기 버전에서 검토한다.

미니홈피 표시 정보

  • 전문가명
  • 전문 분야
  • 활동 지역
  • 자격/경력
  • 현재 상담 상태
  • 좋아요 수
  • 전화하기, 문자 보내기, 상담 요청하기 버튼 (로그인 후 활성화)
상담 가능 응답 지연 가능 상담 불가

8. 전문가 상태 관리

C안: 상태 + 운영시간 구조로 관리한다.

내부 관리 정보

  • 평일 운영시간
  • 주말/공휴일 운영 여부
  • 야간 상담 가능 여부
  • 현재 상태

사용자에게 노출되는 상태

  • 상담 가능
  • 응답 지연 가능
  • 상담 불가
상세 운영시간은 추천 알고리즘과 내부 운영에 활용하고, 사용자에게는 현재 상태 중심으로 간단히 노출한다.

9. 전문가 연결 및 상담 요청 정책

전문가 연결 방식은 혼합형(C안)으로 하되, 모든 연결 액션은 로그인 후 제공한다.
  • 전화하기 (로그인 후 tel: 실행)
  • 문자 보내기 (로그인 후 sms: 실행)
  • 상담 요청하기 (로그인 후 요청 생성)

전화 연결을 선호하는 긴급 사용자를 지원하면서도, 전화를 부담스러워하거나 먼저 메시지로 문의하고 싶은 사용자를 배려한다. 비로그인 사용자가 연결 버튼을 누르면 로그인 바텀시트 또는 로그인 화면으로 전환하고, 로그인 완료 후 기존 전문가/상황 맥락으로 복귀한다.

MVP 상담 연결 처리

  1. 사용자가 상황 입력 또는 전문가 미니홈피에서 연결 액션 선택
  2. 미로그인 상태라면 카카오톡/구글 로그인 및 필수 동의 완료
  3. 로그인 완료 후 기존 입력/전문가 맥락으로 복귀
  4. 전화하기 또는 문자 보내기는 모바일 브라우저의 tel:/sms:로 실행
  5. 상담 요청하기는 로그인 사용자 요청으로 생성·저장

Post-MVP 전문가 응답 루프

  1. 전문가에게 개별 앱 푸시 알림 제공
  2. 전문가가 요청 상세 확인
  3. 전문가가 수락 또는 거절
  4. 전문가가 간단한 답변 메시지 작성 가능
  5. 이후 실제 상담은 전화 연결로 이어질 수 있음
MVP에서는 실시간 채팅방을 만들지 않는다. 상담 요청 생성·저장은 로그인 사용자 기능으로 정의하고, 전문가 앱 푸시·수락/거절·답변 메시지는 Post-MVP 응답 루프로 분리한다.

10. MVP 제외 및 차기 버전 검토 기능

기능MVP 포함 여부비고

게시판제외전문가 요청과 시장 반응 확인 후 검토
전문가 직접 프로필 수정제외초기에는 어드민 관리로 품질 통제
별점 평가제외좋아요만 실제 상담 후 가입자 평가로 사용
AI 추천 이유 필수 표시업그레이드MVP에서는 선택 사항, 향후 필수 기능으로 확장

11. MVP 최종 범위 요약

MVP 포함 (개정 기준)
- Next.js 웹/PWA 소비자 앱
- 비회원 상황 입력 (텍스트/음성)
- 비회원 전문가 둘러보기 및 미니홈피 일부 조회
- 일반 사용자 소셜 로그인 (카카오톡, 구글)
- 필수 동의: 서비스 이용약관, 개인정보 수집·이용, 위치정보 수집·이용
- 선택 동의: 마케팅 정보 수신 및 마케팅 목적 개인정보 활용
- Gemini 기반 상황 분석 (직업 + 카테고리 + 긴급도)
- 로그인 후 전문가 3~5명 추천 확인 (카테고리 우선 → vertical 폴백, 랜덤)
- 카드형 추천 결과 UI + 결과 유지(뒤로가기)
- 전문가 미니홈피 (/expert/[id] 웹 라우트)
- 로그인 후 전화 / 문자 연결 (tel: / sms:)
- 로그인 후 상담 요청 생성·저장
- 어드민: 전문가 등록·카테고리 관리·CSV 일괄등록·감사 로그
- 전문가 상태(3종) + 운영시간 관리

Post-MVP (향후 요구사항에 따라)
- 전문가 앱 푸시 / 수락·거절 / 전문가 답변 메시지
- 전문가 앱 / 전문가 초대 링크 계정 활성화
- 좋아요 평가 구조
- Flutter 네이티브 앱
- auth-social-login.design.md의 기존 비로그인 추천/전화 정책 동기화

제외
- 사진 첨부 / 실시간 채팅 / 게시판
- 별점 평가
- 전문가 직접 프로필 수정
- AI 추천 이유 필수 표시
